# Codex Same-Task Watch

Use only when the user requests a watch. Discover the host's automation tool and read
its current schema. If it supports a heartbeat attached to this exact task, use that;
do not manufacture directives or substitute an unrelated scheduled task. Prefer
updating the matching existing watch to creating a duplicate. An unavailable tool
means this path is unavailable, not permission to invent a shell-based equivalent.

Record: absolute repo root, exact own inbox and socket, native task ID, expected peer
sender and target, run/request nonces, owner, cadence, expiry/stop condition, quiet
policy and last qualification evidence. No secret values in prompts or the ledger.

The watch prompt must read own inbox first, then reconcile current scoped outstanding
requests and durable evidence, using ledger context second. Exact-match identities;
exclude retired seats, closed nonces and unrelated traffic. Date-suffixed identities
are allowed when they are the current registered seat. Return the host's supported
quiet result when nothing actionable changed. Notify only material changes, completion,
failure or a required human decision. Do not claim an XML result format unless the
current host explicitly specifies it.

After arming send a fresh controlled nonce and verify native task re-entry, own-inbox
ACK and a harmless completed check separately. Repeat after restart or task/route
change. Configuration alone is not wake proof. Test independent credential-failure
alerts before unattended reliance; see the cookbook Appendix I.3 and liveness runbook.

Pause/update through the same supported tool on user request or agreed closeout.
Preserve a lifecycle sentinel until final acceptance; name what remains active.
A heartbeat never replaces direct peer delivery, ledger mirror and receiver ACK.
